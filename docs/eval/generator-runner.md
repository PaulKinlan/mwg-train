# Model-driven generator runner (offline-first)

**Status:** generator implementation, not an owner decision or approval to spend. `npm run generate -- --family tr-01 --framework hono --model fireworks/deepseek-v4p1-flash --revision 2cba9e42aa026125f3ed06c6d98c1db82f7ca027 --arm default` produces a stub project and a run record under ignored `.generated-runs/` with **no network call**. `--dry-run true` returns the prompt and build key without writing an app. `--batch path/to/list.json` accepts an array of `{family,framework}` pairs, resumes successful builds by identical identity and stops at first failure; `--retry true` can retry only a failed **offline** run, never a paid call. The live command is `--live true`, but it currently refuses all requests: [generation approval bead `mwg-train-i5i2.1`](https://fleet-manager.exe.xyz/) has no signed amount-scoped approval, and [inference pricing](deepseek-cost-projection.md) for the pinned exact SKU is UNVERIFIED. Do not copy `deepseek-v4-flash-0731` rates to V4.1.

The build key uses `src/eval/build-key.mjs` `evaluationBuildKey`: `project_id@provider/model@decode-sha256:<effective request hash>`. It is hashed as a filesystem directory name because `provider/model` contains `/`; `arm` and the deterministic prompt+revision identity are subdirectories so C1/C2/C3/T cannot overwrite one another. The record includes exact prompt and plan/design hashes, model and 40-character revision, decode config, completion/finish reason, separate prompt/reasoning/content token counts, elapsed time, Node/platform/Chrome version (Chrome **UNVERIFIED** unless recorded by the calling browser gate), and cost **UNVERIFIED** offline. The default, C1, C3 and T prompts get no MWG rules and no uplift; only C2 accepts separately supplied guidance (`--arm c2 --guidance-file <pinned-file>`). C3's deterministic uplift is a subsequent step, **not** applied by this generator. The plan/design text is read from `docs/train/design/<family>/` and is not executed or modified. The generated JSON `{files:[{path,content}]}` is parsed and written as inert text; no `npm install`, import, shell command, dev server, JS evaluation or browser runs in the generator. Only the separately reviewed sandboxed evaluator may later execute the output.

A `finish_reason: length` with empty content writes a FAILED `run.json` and **no project tree**. Other non-`stop` finishes and unsafe paths also fail. Live transport is SSE streamed with a 20-minute hard deadline, **no idle timeout** for long reasoning streams, and one attempt per run. No automatic paid retry: an unknown provider outcome holds its full reserved spend until independently reconciled. The API base URL (`FIREWORKS_BASE_URL`) and key (`FIREWORKS_API_KEY`) come only from the environment, use HTTPS, and never enter the run record or the ledger. The fleet gateway may inject the key on the Linux VM; on macOS the owner supplies a key or tunnel in the environment. Offline development works on either without credentials.

## Live spend guard (intentionally dormant)

The live API must validate a **verbatim, amount-scoped** owner comment on `mwg-train-i5i2.1`, not the bead's description, a lane's comment, an environment cap, or Paul's non-amount-scoped “not worried about cost”. `bd dolt pull` refreshes the ledger, then `bd comments mwg-train-i5i2.1 --json` is read anew for each call; either failing refuses. A newer hub `OWNER-AUTHORIZATION-REVOKED` comment prevents use of an earlier approval. A hub-originated comment must start `OWNER-AUTHORIZATION` and carry `Verbatim: "Authorised: up to N USD in total for DeepSeek V4.1 Flash generation; stop and ask at P%."`, `Scope: generation`, `Model: fireworks/deepseek-v4p1-flash`, `Cap-USD: N`, `Stop-at-pct: P`, `Expiry: <ISO UTC>`, `Ledger-host: <hostname>`, `Signature: hmac-sha256:<hex>`. The HMAC payload is `mwg-train-i5i2.1`, then verbatim, scope, model, cap, expiry, stop percent and ledger hostname, newline-delimited; the hub keeps `MWG_AUTH_VERIFY_KEY` outside all repos and signs only after verifying Paul's actual exact words, date/channel and intent. This signature is an additional relay-integrity check, **not a substitute for approval**. A commenter name alone is spoofable through `BEADS_ACTOR`. A signed approval binds a single host, so other VMs (and a Mac) cannot independently spend against separate ledgers under one cap. Do not share the signing key with untrusted code.

The quote must be a reviewed exact-model inference row in `docs/eval/quotes.jsonl`, product `inference (exact model)`, model `fireworks/deepseek-v4p1-flash`, Fireworks serverless per-token mode, with source URL/SHA-256 and verified input/output/reasoning prices plus billing minimum. **No such row currently exists.** A provider GPU-hour plan needs a different billing-mode implementation and a GPU-duration bound; do not force it through per-token arithmetic. Also required: an independently verified prompt-token upper bound (the CLI currently supplies none), the pinned `max_tokens` cap, and a private `MWG_SPEND_LEDGER_PATH` on the named host. The guard computes a conservative maximum per call at the higher of reasoning/output token price for every allowed completion token, plus prompt upper bound and billing minimum. It reserves that upper bound under an atomic same-host lock in an append-only JSONL ledger with scope and bead ID, flushes to disk **before** network access, and counts unsettled reservations against `cap × stop_pct/100`. An uncertain response is never refunded by assumption. A completed settlement records token usage and actual cost where provider usage permits calculation. Corrupt ledgers, held/stale locks, duplicate calls, unknown model rates, invalid signing, expired approval and cap exhaustion all refuse before network access; a stale lock requires manual reconciliation, not automatic lock stealing. All later live requests must run on this one named host with the shared ledger. No generated code receives its path or signing key.

This is deliberately more restrictive than a permissive sample client. Before enabling live generation, the hub must obtain Paul's amount-scoped consent, publish a correct signed bead comment, pin and independently review exact inference billing, establish a measured tokenizer and a conservative prompt upper bound, and verify the runner's one-host ledger policy. `mwg-train-i5i2.11` handles the first paid vertical slice only after these conditions, never as part of `npm run check:all` or the offline tests.
