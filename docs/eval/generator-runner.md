# Model-driven generator runner (offline by default)

`npm run generate -- --family tr-01 --framework hono --model deepseek/deepseek-flash --revision 2cba9e42aa026125f3ed06c6d98c1db82f7ca027 --arm default` writes an **offline stub**, not a model response, beneath ignored `.generated-runs/`. `--dry-run true` returns the prompt/build key without writing an app; `--batch path/to/list.json` accepts up to 210 `{family,framework}` entries. Reusing an identical successful identity resumes without sending another request; the identity includes the backend, so a prior offline stub can never masquerade as a successful live call. A **live** identity with a ledger reservation is **permanently consumed**, including an HTTP 5xx or a process killed after reservation: there is no reconcile command or same-identity paid retry. Missing credentials, unreadable authority and corrupt/locked ledger refuse before a run directory is created; when no reservation was written, correcting the preflight cause may reuse that identity. An unfinished directory with no `run.json` remains `RUN_IN_PROGRESS`; only the narrowly scoped [empty pre-reservation orphan procedure](#manual-recovery-of-an-empty-pre-reservation-orphan) permits removing it after human verification. Never erase an uncertain paid attempt. Preserve `run.json` and the append-only ledger for reserved attempts, check the provider invoice separately, and record that attempt as failed or not evaluable; do **not** delete paid artifacts, edit ledger rows, or change an arm just to bypass refusal. A new prompt/decode/revision is a new study identity only after its normal review/preregistration, never an implicit recovery of the old sealed cell. `--retry true` is offline-only.

`--live true` requires the exact native DeepSeek integration base `DEEPSEEK_BASE_URL=https://deepseek.int.exe.xyz/v1`, a privately injected `DEEPSEEK_API_KEY`, and a private append-only `MWG_SPEND_LEDGER_PATH`. The runner composes `/chat/completions`; it refuses different origins/paths and credential-bearing URLs before authority lookup or reservation. It makes **one** model request per new build identity. The runner does not fetch credentials during offline/dry runs. The owner decision on [`mwg-train-i5i2.1`](https://fleet-manager.exe.xyz/) explicitly authorizes DeepSeek V4.1 Flash **generation without a dollar cap**; it does not authorize a different model, training, serving, or changing sealed evaluation sets. Every live request first pulls Beads and requires that bead to be closed with the **exact code-pinned owner decision**. If the pull, decision, or comments cannot be read, live generation refuses. Any comment **on that bead** containing `OWNER-AUTHORIZATION-REVOKED` **anywhere**, case-insensitively (including Markdown wraps or a reason), refuses. Denial is not tied to an author allowlist: both the owner's dashboard identity and the relay that recorded the decision can differ from a hub lane name. A forged or quoted marker can cause a false-positive stop, but a spoofable `BEADS_ACTOR` name never grants positive authorization. The code-reviewed close reason and provisioned API key are runtime trust anchors, **not cryptographic proof of Paul's chat provenance**. Change positive authorization only through reviewed code; to revoke, place the marker in a comment on the decision bead.

## Manual recovery of an empty pre-reservation orphan

This is **not** a paid retry or a ledger reconciliation command. A crash between creating a live run directory and reserving its request ID may leave a directory without `run.json`, project files or any ledger row. In that state `RUN_IN_PROGRESS` deliberately refuses automatic cleanup because another process may still be running. An operator may perform the following out of band, on the executing host only:

1. Quiesce **all** generators for this build identity and verify that no process is currently writing the directory; prevent another launch until the inspection is finished. Do not infer inactivity merely because `run.json` is absent.
2. Re-derive the exact `output_dir` from the same build inputs with `--live true --dry-run true` (no provider request or directory write). Its final directory component is the deterministic live `requestId`. Inspect the configured, private, persistent ledger for that exact ID, including `reserve` and `settle` rows. If the ledger is unreadable/corrupt, the path is different, or **any** reservation exists (settled or uncertain), stop: preserve the directory and never resend the call.
3. Only with an intact ledger proving **no** reservation, no active writer and a truly **empty** run directory (no `run.json`, hidden entries or partial project), use `rmdir` on that exact `output_dir`; it refuses nonempty directories. Record the manual check in the run's operational bead. Do not use `rm -rf`, delete a ledger row, clear a ledger lock, or change an arm to bypass a paid identity.
4. After the empty orphan is removed, a fresh live command may use the same identity. It still refreshes owner authority and rechecks the ledger atomically before fetch. If `rmdir` fails or any evidence is ambiguous, keep `RUN_IN_PROGRESS` and escalate instead of guessing.

**Credential provisioning on both platforms:** The fleet Linux VM stores the integration credentials outside any repo and injects `DEEPSEEK_API_KEY` into the operator process without echoing or committing it. Set `DEEPSEEK_BASE_URL` to the pinned HTTPS `/v1` base and `MWG_SPEND_LEDGER_PATH` to a private persistent path; the generator never auto-loads a repository `.env`. A Mac needs its own injected key, Beads CLI and Dolt remote because each live request rechecks authority. Neither platform may run a generated app outside the approved i5i2.5 containment path.

The private ledger reserves the deterministic live request ID (SHA-256 of build key, supplied revision, backend, arm and exact prompt hash) under a single-host atomic lock, appending and syncing a `reserve` row **before** contacting the provider. It includes the model, supplied revision, project ID, decision bead, and a projected USD cost or `UNVERIFIED`. Even if an artifact directory is deleted, a prior reservation for the same identity (settled or uncertain) refuses another paid call; a deliberately different arm or prompt gets a different ID. Duplicate IDs, corrupt/torn ledgers, held locks and missing authority refuse before the request; preflight checks read the ledger before allocating a run directory and reservations are rechecked atomically. Locks are never stolen automatically. A subsequent `settle` row records prompt, completion, reasoning and content tokens (null where the provider did not supply them), completion status, and `computedUsd` or `UNVERIFIED`. If settlement fails, `run.json` records `LEDGER_UNSETTLED`; preflight policy refusals use `SPEND_GUARD` or `NO_OWNER_AUTH` rather than a generic provider-error code. Do not retry a potentially charged call. Different hosts need separate private ledgers; there is **no cross-host dollar ceiling** to coordinate under Paul's no-cap decision. Do not give untrusted generated code access to credentials or this ledger.

**Cost is accounting, not a spend gate.** The native DeepSeek integration response may supply usage, not an invoice. `run.json` records token categories, `projected_cost_usd`, `computed_cost_usd`, and `cost_source_sha256`; the latter three are `UNVERIFIED` absent an applicable quote and token bound. A numeric estimate requires a reviewed exact-model native DeepSeek **inference** quote in `docs/eval/quotes.jsonl` (per-token rates, source URL and SHA-256); it must not borrow Fireworks, training or `deepseek-v4-flash-0731` prices. A missing quote or measured prompt-token upper bound does **not** block an otherwise authorized live call. Even a numeric `computed_cost_usd` is a **rate-based estimate**, not the actual provider bill; reconcile the account invoice separately. Unknown cost is never $0. `run.json` records the full prompt and plan/design hashes, native build-key/decode identity, exact requested API model and endpoint, **caller-supplied** 40-hex HF reference, `resolved_revision: UNVERIFIED`, provider response model if supplied, usage, finish reason, wall time, platform/Node and Chrome version (`UNVERIFIED` until a browser gate supplies it). The proxy alias is not an immutable checkpoint attestation. For a completed live response, `model-response.txt` (private `0600`, write-once) preserves the raw text and its SHA-256 **before** JSON validation, including invalid model output; a failed or uncertain paid identity is never retried.

The runner reads `docs/train/design/<family>/plan.md` and `design.md`, sends text only (never target/reference images), parses a bounded JSON `{files:[{path,content}]}` response into a build-keyed directory and writes those files as inert data. It never imports, executes, installs or serves model-generated code. A `finish_reason: length` with empty content yields a failed `run.json` and no project. A 20-minute hard stream deadline (no idle deadline) and no automatic paid retries prevent silent runaway calls. Browser/sandbox evaluation and sealed preregistration remain separate reviewed work.
