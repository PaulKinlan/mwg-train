# Model-driven generator runner (offline by default)

`npm run generate -- --family tr-01 --framework hono --model fireworks/deepseek-v4p1-flash --revision 2cba9e42aa026125f3ed06c6d98c1db82f7ca027 --arm default` writes an **offline stub**, not a model response, beneath ignored `.generated-runs/`. `--dry-run true` returns the prompt/build key without writing an app; `--batch path/to/list.json` accepts up to 210 `{family,framework}` entries. Reusing an identical successful identity resumes without sending another request. A failed or interrupted **live** identity cannot retry in place; inspect/reconcile it before issuing a new request. `--retry true` is offline-only.

`--live true` requires a Fireworks HTTPS chat-completions endpoint (`FIREWORKS_BASE_URL`), `FIREWORKS_API_KEY`, and a private append-only `MWG_SPEND_LEDGER_PATH`. It makes **one** model request per new build identity. The runner does not fetch credentials during offline/dry runs. The owner decision on [`mwg-train-i5i2.1`](https://fleet-manager.exe.xyz/) explicitly authorizes DeepSeek V4.1 Flash **generation without a dollar cap**; it does not authorize a different model, training, serving, or changing sealed evaluation sets. Every live request first pulls Beads and requires that bead to be closed with the **exact code-pinned owner decision**. If the pull, decision, or comments cannot be read, live generation refuses. Any comment by a trusted spend-control actor on that bead containing `OWNER-AUTHORIZATION-REVOKED` **anywhere**, case-insensitively (including Markdown wraps or a reason), refuses. This deliberately errs toward denial even for a quoted marker; a spoofable `BEADS_ACTOR` name is never sufficient to grant positive authorization. The code-reviewed close reason and provisioned API key are runtime trust anchors, **not cryptographic proof of Paul's chat provenance**. Change/revoke this policy only through reviewed code or a trusted revocation comment.

The private ledger reserves a unique request ID under a single-host atomic lock, appending and syncing a `reserve` row **before** contacting the provider. It includes the model, supplied revision, project ID, decision bead, and a projected USD cost or `UNVERIFIED`. Duplicate IDs, corrupt/torn ledgers, held locks and missing authority refuse before the request; locks are never stolen automatically. A subsequent `settle` row records prompt, completion, reasoning and content tokens (null where the provider did not supply them), completion status, and `computedUsd` or `UNVERIFIED`. If settlement fails, `run.json` records `LEDGER_UNSETTLED`; do not retry a potentially charged call. Different hosts need separate private ledgers; there is **no cross-host dollar ceiling** to coordinate under Paul's no-cap decision. Do not give untrusted generated code access to credentials or this ledger.

**Cost is accounting, not a spend gate.** The Fireworks inference response supplies usage, not an invoice. `run.json` records token categories, `projected_cost_usd`, `computed_cost_usd`, and `cost_source_sha256`; the latter three are `UNVERIFIED` absent an applicable quote and token bound. A numeric estimate requires a reviewed exact-model **inference** quote in `docs/eval/quotes.jsonl` (Fireworks serverless per-token rates, source URL and SHA-256); it must not borrow training or `deepseek-v4-flash-0731` prices. A missing quote or measured prompt-token upper bound does **not** block an otherwise authorized live call. Even a numeric `computed_cost_usd` is a **rate-based estimate**, not the actual provider bill; reconcile the account invoice separately. Unknown cost is never $0. `run.json` records the full prompt and plan/design hashes, build-key/decode identity, model and **caller-supplied** 40-hex revision, finish reason, wall time, platform/Node and Chrome version (`UNVERIFIED` until a browser gate supplies it). A supplied revision is not independently verified as a provider deployment revision; do not claim checkpoint parity from this field alone.

The build key is `src/eval/build-key.mjs`'s `evaluationBuildKey` (`project_id@provider/model@decode-sha256:<hash>`), shared with the evaluator. `stream:true` is transport, not a changed decode configuration. Default, C1, C3 and T have **no** guidance; only C2 accepts a separately pinned `--guidance-file`. C3's deterministic uplift is a later stage, not part of this generator. The runner reads `docs/train/design/<family>/plan.md` and `design.md`, sends text only (never target/reference images), parses a bounded JSON `{files:[{path,content}]}` response into a build-keyed directory and writes those files as inert data. It never imports, executes, installs or serves model-generated code. A `finish_reason: length` with empty content yields a failed `run.json` and no project. A 20-minute hard stream deadline (no idle deadline) and no automatic paid retries prevent silent runaway calls. Browser/sandbox evaluation and sealed preregistration remain separate reviewed work.
