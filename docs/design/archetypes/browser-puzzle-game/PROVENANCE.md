# Signal Grid reference-board provenance

- **Scope:** eight committed 1376 × 768 JPEGs for the [Signal Grid archetype](README.md): four Light and four Dark. The table pins the exact bytes currently in the tree. These are illustrative storyboards, not a working game.
- **Verified original:** Only `step1-board-initial.jpg` retains the original owner-authorised `mwg-train-1ddf` (2026-10-14 UTC) generation record. That record reports the `image-generator` subagent, `gemini-3.1-flash-image`, the exact generation-input prompt digest `8ce1119f…` and the visual verdict below. That digest is the block that was actually sent, and it stays in the `Original generation-input prompt SHA-256` column: the theme-control amendment changed the README block afterwards, so the current text is pinned in the adjacent column instead of overwriting the receipt. It is **not** evidence for any of the seven subsequently installed boards.
- **Seven unverified imports:** In commit `15409c2b8`, three Light files were replaced and four Dark files added from machine-local scratch JPEGs. The response payload, attested `modelVersion`, exact generation prompts and source receipts were not preserved. The installed bytes therefore have **unknown model and generator-prompt provenance**. `gemini-3.1-flash-image` is the response recorded for the *original* Light boards, not these replacements; the later generator's configured `gemini-nano-banana-2.1` does not attest them either. The authored README prompt hashes below are references to the design briefs, **not** hashes of the seven unrecorded generation inputs. Neither the JPEG hashes nor the frame scanner establishes a model or a prompt.
- **Reproduction:** The seven scratch-file imports have been removed from `scripts/generate-archetype-light-dark.mjs`. Requests including this family fail before paid generation until authentic source receipts or an owner-authorised, tariff-bounded, attested regeneration route is available. The current JPEGs remain illustrative but must not be described as attested, reproducible generation.
- **Rights:** `excluded_from_training: true`; `approved_for_training: false`. The original [consumer-account service](../../../provenance/accounts/google-antigravity-consumer.md) record does not establish a provider, training licence, commercial product rights or exclusive ownership for the seven imported replacements. Withhold all seven from training; neither an authored prompt nor a copied JPEG grants reuse clearance.
- **What the frames do not prove:** 440 Hz and 660 Hz are fictional puzzle tokens; collision at D4, 14 accepted moves, 01:48 playtime, 38 games played, 97% win rate, current streak 12, best streak 19 and clipboard confirmation are storyboard states. A still image cannot establish a playable solution, WebAudio, keyboard/pointer parity, accurate stats, saved state or clipboard success. The [functional plan](plan.md) requires driven tests before any such claim.
- **Theme-control deviation (mwg-train-zeci):** all eight committed boards emphasise the same DAYLIGHT segment of the “Daylight / Night” pill, including the four night-mode boards, so the depicted control state contradicts the depicted theme and the Light/Dark pairs do not differ in it. The brief now requires the ACTIVE theme's segment to be filled and carry a check glyph and states the Light page for every step, so each step's Daylight board marks `DAYLIGHT` against a `dark/` twin that marks `NIGHT` ([README](README.md#theme-control-state)); `npm run check:state-controls` holds the brief to it, including the rule that every twin pair must mark different segments. The committed bytes were not edited - a replacement needs the amount-scoped approval the README withholds - so they remain illustrative and **known non-conforming** to that section; this register pins what exists, not what the brief requires.

Only the original Step 1 record binds such a digest to specific generated bytes, and it does so through the `Original generation-input prompt SHA-256` column, which holds the block that was sent (`8ce1119f…`) and is not rewritten when the brief changes. The `Authored README prompt block SHA-256` column records the text as it stands now, so the theme-control amendment shows up as a new digest beside the preserved receipt instead of silently re-pointing the original receipt at newer text. For the other seven boards, the register records authored intent and committed-image identity, not a generation receipt; the step 3 and step 4 digests were re-pinned after those briefs were stated as the Light half of their pairs.
