## Known deviation: the committed inspector renders Markdown source

Bead `mwg-train-e3ne` (recorded 2026-10-20, evidence `design-evidence/mwg-train-4l9x/saas-inspector-markdown.png`, inspector region x=1056-1376 y=300-560 at 200%) found that each of the four boards depicts the issue inspector as an unstyled Markdown dump: the rendered UI copy contains literal heading hashes (`### Description`, `### Impact`) as body text and shows `spi_driver.c` wrapped in visible backticks. That contradicts the archetype's own premise — the inspector is the "operate" surface and the most text-dense region of the board, so it teaches literal Markdown syntax instead of a designed panel.

The images are **retained unchanged** because no image-model call is authorised for this fix. The [README](README.md) step briefs were amended to require rendered product copy: inspector section headings as clean titles (“Description”, “Impact”) with no leading hashes, and code identifiers in a monospace face with backticks stripped. The **generation-input** digests above therefore stay pinned to the text that actually produced the committed bytes, and the **amended authored** digests pin the text a conforming replacement would be generated from. Until such a replacement lands with its own authorisation, spend reservation, prompt digest, JPEG digest and vision receipt, these four boards are known non-conforming in exactly that region and must not be cited as evidence for rendered-copy typography.

The [README](README.md) carries the amended source text for the **amended authored** column. Compute `sha256(UTF-8 bytes between each \`\`\`text fence, omitting the final linefeed)`. The **generation-input** column is the digest of the prompt text as sent; that text is the pre-amendment revision of the same README, unchanged since commit `80290293`, and is reproducible byte-for-byte with `git show 80290293:docs/design/archetypes/saas-workspace-board/README.md`.
