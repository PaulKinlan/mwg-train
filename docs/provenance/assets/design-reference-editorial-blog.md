# Provenance: editorial blog archetype visual reference boards

- **Scope:** four illustrative JPEGs for `editorial-blog`, an archetype authored on the archetype type axis (bead `mwg-train-efg`) rather than one of the five evaluation families. It is the first archetype added outside that sealed set, and this record exists so nobody has to guess which side of that boundary it sits on: **A1, planning reference only** - not an evaluation target, not a training example, not generated-site evidence.
- **Generation:** 2026-10-11 UTC, by `scripts/generate-archetype-boards.mjs --write --only editorial-blog`. The script passes `model: gemini-nano-banana-2.1` explicitly to the project's model gateway (`https://gemini.int.exe.xyz/v1beta/models/gemini-nano-banana-2.1:generateContent`, overridable with `MWG_TRAIN_IMAGE_ENDPOINT`) and fails closed unless the response's own `modelVersion` equals the requested model, so all four boards are gateway-attested `gemini-nano-banana-2.1`. Recorded settings: `responseModalities: ["IMAGE"]`, temperature 0.7, `maxOutputTokens` 8192; each board returned a 1376 × 768 JPEG. No seed was set, so the bytes are not reproducible from the prompts. The prompts are the four in the linked archetype README, and their exact UTF-8 digests are in the table below, so a regeneration can be proven to have used the same brief.
- **Rights:** [Google consumer-account terms](../accounts/google-antigravity-consumer.md) prohibit using AI-generated service content to develop machine-learning models. `excluded_from_training: true`; `approved_for_training: false` for **all four**. No exclusive copyright, general image license, production or commercial reuse clearance is claimed, and no separate reuse/clearance document was supplied. Do not move these images into a corpus, an evaluation target, adapter or training work, or generated-site evidence. A visual review does not change that boundary.
- **Visual truth:** the publication name, headlines, bylines, dates, article text, tag names and share counts are invented, unverified placeholders. The JPEGs do not demonstrate a working index, search, deep link, share path, composer or accessible reading experience, and they do not describe the archetype's contract: the pictures are broader than any behaviour that has been implemented.
- **Observed placeholder artefacts, inspected and accepted:** an independent vision review of this 2026-10-11 set (commissioned from a vision-capable model in a different family than the lane that produced the boards, which is text-only) found **no corrupted text in a primary position** - the defect class that got the previous board set rejected by the owner on sight - and judged the set ACCEPTABLE as planning reference, explicitly recommending against a re-roll. Its per-board findings, recorded rather than smoothed over:
  - `step1-index.jpg`: clean. Masthead, nav, search field, five excerpt cards with headline, excerpt, byline, date and reading time, and the Editor's Pick badge all read correctly. One quirk outside the page viewport: the browser chrome shows `thekiin.com`.
  - `step2-article.jpg`: clean in every primary position (breadcrumb, serif headline, byline, subheadings, pull quote, figure caption, share row with a `Link Copied!` tooltip, tags). Body paragraph 2 degrades into diffusion artefacts - `lves`, a repeated `copper oxide is starved`, `tnemerating`, `shougnen terrtormial` - and paragraph 1 misspells `kiln` as `klln`. The figure and the related-article cards render in a right-hand sidebar rather than inline; the prompt asked for a single column of prose and the prose is single-column, so this is a layout variation rather than a missing element.
  - `step3-composer.jpg`: the two columns, the labelled fields, the live preview and the sticky action bar are all correct and readable. It carries the most artefacts of the four: a wizard stepper the prompt never asked for, whose active step renders this brief's own heading text as UI (`Step 3: Author Article Composer`) - prompt leakage, not page content - plus `1. Detalis` in that stepper, `Kiin Vlllage` in a tag chip, `Pubiishing makes the article reachable by its own link.` in the note under the publish button, and a garbled trailing fragment in the body textarea (`To renanden the propsed to riss rresentation.`).
  - `step4-empty.jpg`: clean. The query `soda firing schedule`, the no-match heading quoting it, the nearby-tag suggestion and the `Clear search` action all read correctly.
  - Cross-board: the publication name is consistent (`The Kiln Chronicle`) across all four. Dates differ between boards because the prompts specify them differently (October 2024 on the index, `12 October 2026` on the article), and the tag vocabulary drifts between the two index boards (`Glaze Chemistry`/`Studio Notes` against `Glazing`/`Studio News`) because no prompt pins it.
  - **Decision, and who made it:** accepted as generated, no re-roll. The artefacts above sit in interior prose, in invented chrome and in placeholder tag values; every label, button, headline and control a reader would act on reads correctly, and the independent review - the check that exists precisely to find this class of defect - recommended against spending a billed model call on a re-roll. Re-rolling one board is a single command (`--board step3-composer.jpg`) if a later reader disagrees; what is not acceptable is a record that implies these boards were clean.
- **Coverage:** four boards, chosen so a journey can be written against a reader and an author without inventing a fifth state - the index, an article reached by deep link, the author's composer, and the empty-search state. Error and offline states are **not** pictured and must not be inferred from these images.
