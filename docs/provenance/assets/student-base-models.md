## Qwen (Apache-2.0) — the clean case

The `Qwen/Qwen2.5-Coder-7B-Instruct` LICENSE file fetched from the repo
(`hf-license-qwen25-coder-7b`, 11343 bytes) is the Apache License 2.0 text and contains the
operative grant:

> 2. Grant of Copyright License. Subject to the terms and conditions of this License, each
> Contributor hereby grants to You a perpetual, worldwide, non-exclusive, no-charge, royalty-free,
> irrevocable copyright license to reproduce, prepare Derivative Works of, publicly display,
> publicly perform, sublicense, and distribute the Work and such Derivative Works in Source or
> Object form.

There is no field-of-use restriction, no acceptable-use policy incorporated by reference, and no
restriction on publishing derived weights. Redistribution conditions are the ordinary Apache ones
(licence copy, NOTICE retention, prominent change notices).

| Right | Qwen (Apache-2.0) |
| --- | --- |
| Train on it | YES |
| Publish derived / fine-tuned weights | YES |
| Commercial use | YES |

**Recommended initial student base: `Qwen/Qwen2.5-Coder-7B-Instruct`** at revision
`c03e6d358207e414f1eca0bb1891e29f1db0e242`. Reasons: 7B keeps a QLoRA feasibility run on one rented
GPU, it is a code model (the experiment's target behaviour is code generation), the licence is
Apache-2.0 with no pass-through obligations, and the hub metadata is stable (last modified
2025-01-12). `Qwen3-8B` is the comparable general-purpose alternative if the pilot shows the task is
more about reasoning than code.

## Gemma 3 (Gemma Terms of Use) — allowed, but the obligation is viral

The Gemma licence is not a flat open licence, and one clause changes the shape of the whole
teacher/student arm. `gemma-terms.txt` (sha256 `3344b876639e8f94`, last modified April 1, 2026),
definition 1.1(e), extracted lines 254-260:

> "Model Derivatives" means all (i) modifications to Gemma, (ii) works based on Gemma, or (iii) any
> other machine learning model which is created by transfer of patterns of the weights, parameters,
> operations, or Output of Gemma, to that model in order to cause that model to perform similarly to
> Gemma, including distillation methods that use intermediate data representations or methods based
> on the generation of synthetic data Outputs by Gemma for training that model. For clarity, Outputs
> are not deemed Model Derivatives.

So a model trained on **synthetic data generated by Gemma** is itself a Gemma Model Derivative. Any
model we fine-tune *from* Gemma weights is a Model Derivative for the simpler reason that it is a
modification of Gemma. Section 3.1, extracted lines 284-292, then conditions distribution:

> You may reproduce or Distribute copies of Gemma or Model Derivatives if you meet all of the
> following conditions:
> You must include the use restrictions referenced in Section 3.2 as an enforceable provision in
> any agreement (e.g., license agreement, terms of use, etc.) governing the use and/or distribution
> of Gemma or Model Derivatives and you must provide notice to subsequent users you Distribute to
> that Gemma or Model Derivatives are subject to the use restrictions in Section 3.2.
> You must provide all third party recipients of Gemma or Model Derivatives a copy of this
> Agreement.
> You must cause any modified files to carry prominent notices stating that you modified the files.

And Section 3.2 incorporates the Gemma Prohibited Use Policy by reference (`gemma-prohibited-use`,
captured), while Section 3.3 says (extracted line 317):

> Google claims no rights in Outputs you generate using Gemma. You and your users are solely
> responsible for Outputs and their subsequent uses.

| Right | Gemma 3 |
| --- | --- |
| Train on it | YES |
| Publish derived / fine-tuned weights | YES, **but** the model stays a Model Derivative: pass through the Section 3.2 use restrictions as an enforceable provision, include the Agreement, and add the Gemma notice file |
| Commercial use | YES, subject to the Prohibited Use Policy |

This is a pass-through obligation on the published artefact, not a prohibition. It is still a real
reason to prefer Qwen for the first run: an Apache-2.0 student leaves nothing to pass through.

## Consequence for the experiment

1. **Student base: Apache-2.0 Qwen, pinned by revision sha.** No eligibility question, no
   pass-through, no gating.
2. **A Gemma teacher arm is not "free"**: any student model trained on Gemma outputs inherits the
   Gemma Terms as a Model Derivative, so the published weights would have to carry Gemma's use
   restrictions. If a Gemma teacher arm is run, it is a separate experimentally-tagged arm with a
   different published artefact, not a row in the main corpus.
3. **The open teacher SKUs matter for a second reason.** DeepSeek-V4-Flash and GLM-5.3-Flash are
   MIT-licensed weights (see `../accounts/deepseek-api.md` for the DeepSeek API terms). Serving one
   of those checkpoints ourselves, rather than calling the hosted API, changes which terms apply:
   the MIT licence on the weights governs our use of the model, and the provider's API terms — the
   ones that make DeepSeek the only teacher whose terms permit distillation — stop applying to a
   self-hosted copy. That is a cheaper and more defensible route for a teacher arm than an API
   account, and it should be priced in the pilot.
4. **Re-verify at run time.** A licence can change and a repo can be re-tagged. Every training run
   must record the revision sha it actually loaded and the licence text captured on that date.
