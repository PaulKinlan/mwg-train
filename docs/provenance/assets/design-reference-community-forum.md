# Provenance: community-forum archetype visual reference board

- **Scope:** one illustrative JPEG for `community-forum`, an in-family training archetype (`tr-20`, folk-music forum with musician notes, and the `fam-14` variant, one of the sixteen in `src/eval/prereg.mjs`) rather than one of the five evaluation families. It exists because the archetype's plan asserts a refusal contract - a contribution missing a strictly required field is refused with HTTP 400 and an inline validation alert, and nothing is stored - and the board set for that state was empty (`mwg-train-tzy0`, per [`reference-board-gaps.md`](reference-board-gaps.md)). This record exists so nobody has to guess which side of the boundary it sits on: **A1, planning reference only** - not an evaluation target, not a training example, not generated-site evidence.
- **Generation:** 2026-10-13 UTC, by `scripts/generate-archetype-boards.mjs --write --only community-forum`. The script passes `model: gemini-nano-banana-2.1` explicitly to the project's model gateway (`https://gemini.int.exe.xyz/v1beta/models/gemini-nano-banana-2.1:generateContent`, overridable with `MWG_TRAIN_IMAGE_ENDPOINT`) and fails closed unless the response's own `modelVersion` equals the requested model, so the board is gateway-attested `gemini-nano-banana-2.1`. Recorded settings: `responseModalities: ["IMAGE"]`, temperature 0.7, `maxOutputTokens` 8192; the board returned a 1376 × 768 JPEG. No seed was set, so the bytes are not reproducible from the prompt. The prompt is the one in the linked archetype README, and its exact UTF-8 digest is in the table below, so a regeneration can be proven to have used the same brief.
- **Rights:** [Google consumer-account terms](../accounts/google-antigravity-consumer.md) prohibit using AI-generated service content to develop machine-learning models. `excluded_from_training: true`; `approved_for_training: false`. No exclusive copyright, general image license, production or commercial reuse clearance is claimed, and no separate reuse/clearance document was supplied. Do not move this image into a corpus, an evaluation target, adapter or training work, or generated-site evidence. A visual review does not change that boundary.
- **Visual truth:** the forum name, thread title, note bodies, author names, tune tags and error strings are invented, unverified placeholders. The JPEG does not demonstrate a working forum, moderation state, keyboard operability or a validation engine, and it does not by itself satisfy the archetype's contract: the refusal behaviour is asserted by the plan and its verifiers, not by this picture.
- **Observed placeholder artefacts, inspected and accepted:** an independent vision review of this 2026-10-13 board (commissioned from a vision-capable model in a different family than the lane that produced it, which is text-only) returned ACCEPT. It quoted the alert "Your note was not posted" and the inline message "Write something before posting" beneath the Note field; confirmed the Note body is the ONLY field in error while Author Name is filled and unstyled; confirmed existing thread notes with author names sit above the composer; and read the thread, filter and button text ("The Tune Archive", "Discussion thread", "The Maid Behind the Bar (Reel)", "All Tunes", "Reels", "Jigs", "Post note", "Cancel") without corruption. This record does not imply the board was clean beyond what that review quoted.
- **Coverage:** one board, for the reply-composer refusal only. The plan's five other states (`step1-browse`, `step2-thread`, `step3-composer`, `step4-moderation`, `step5-empty`) are **not** pictured and must not be inferred from this image.
- **Where the state renders, and the comparator's scope boundary:** the refusal is a re-render of the reply composer after a refused submission, so `board-states.json` maps this board to a deliberately null path with a source. As an interaction board it establishes the canonical visual reference under `kind: 'interaction'` with a null path, per the Wave 2 standard (booking `step4-error.jpg`; contact-lead, account-recovery and event-registration `step3-refusal`), and it is exempt from path-based comparator sweeps: `captureSignature` captures by URL, so reaching a refusal requires driving the refused submission, which is deferred to dynamic interaction capture in `check-cross-arm-parity` and is instrument work rather than a board task.
