# Provenance: expense-tracker archetype visual reference board

- **Scope:** one illustrative JPEG for `expense-tracker`, an in-family training archetype (`tr-15`, `tr-29`, `fam-15` and `fam-r03`; one of the sixteen in `src/eval/prereg.mjs`) rather than one of the five evaluation families. It exists because the archetype's plan asserts a numeric-integrity refusal - a negative or blank amount is refused with an accessible validation error and nothing is added, so a corrupt value cannot enter the running total - and the board set for that state was empty (`mwg-train-skm3`, per [`reference-board-gaps.md`](reference-board-gaps.md)). This record exists so nobody has to guess which side of the boundary it sits on: **A1, planning reference only** - not an evaluation target, not a training example, not generated-site evidence.
- **Generation:** 2026-10-13 UTC, by `scripts/generate-archetype-boards.mjs --write --only expense-tracker`. The script passes `model: gemini-nano-banana-2.1` explicitly to the project's model gateway (`https://gemini.int.exe.xyz/v1beta/models/gemini-nano-banana-2.1:generateContent`, overridable with `MWG_TRAIN_IMAGE_ENDPOINT`) and fails closed unless the response's own `modelVersion` equals the requested model, so the board is gateway-attested `gemini-nano-banana-2.1`. Recorded settings: `responseModalities: ["IMAGE"]`, temperature 0.7, `maxOutputTokens` 8192; the board returned a 1376 × 768 JPEG. No seed was set, so the bytes are not reproducible from the prompt. The prompt is the one in the linked archetype README, and its exact UTF-8 digest is in the table below, so a regeneration can be proven to have used the same brief.
- **Rights:** [Google consumer-account terms](../accounts/google-antigravity-consumer.md) prohibit using AI-generated service content to develop machine-learning models. `excluded_from_training: true`; `approved_for_training: false`. No exclusive copyright, general image license, production or commercial reuse clearance is claimed, and no separate reuse/clearance document was supplied. Do not move this image into a corpus, an evaluation target, adapter or training work, or generated-site evidence. A visual review does not change that boundary.
- **Visual truth:** the ledger name, department names, amounts, dates, running total and error strings are invented, unverified placeholders. The JPEG does not demonstrate a working ledger, server persistence, budget arithmetic or a validation engine, and it does not by itself satisfy the archetype's contract: the refusal behaviour is asserted by the plan and its verifiers, not by this picture.
- **Observed placeholder artefacts, inspected and accepted:** an independent vision review of this 2026-10-13 board (commissioned from a vision-capable model in a different family than the lane that produced it, which is text-only) returned ACCEPT. It quoted the alert "This expense was not recorded" and the inline message "Enter an amount greater than zero" on the amount field alone; confirmed the Description, Department and Date fields are filled with no error styling; and confirmed the running-total panel still shows its previous value with no line added. The review read the amount field as `0.00`, which is coherent with the prompt's refusal ("greater than zero") and with the plan's "negative or blank amount" assertion - the refusals are the same state. This record does not imply the board was clean beyond what that review quoted.
- **Coverage:** one board, for the entry refusal only. The dashboard, ledger list, budget allocation and confirmation states are **not** pictured and must not be inferred from this image. The plan records that the landing references for the training families exist under `docs/design/training/` and are pinned in [`training-reference-boards.md`](training-reference-boards.md); those are a different artefact class (training-family landing pages), and this archetype board is pinned here.
- **Where the state renders, and the comparator's scope boundary:** the refusal is a re-render of the entry form after a refused submission, so `board-states.json` maps this board to a deliberately null path with a source. As an interaction board it establishes the canonical visual reference under `kind: 'interaction'` with a null path, per the Wave 2 standard (booking `step4-error.jpg`; contact-lead, account-recovery and event-registration `step3-refusal`), and it is exempt from path-based comparator sweeps: `captureSignature` captures by URL, so reaching a refusal requires driving the refused submission, which is deferred to dynamic interaction capture in `check-cross-arm-parity` and is instrument work rather than a board task.
