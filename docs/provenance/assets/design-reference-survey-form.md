# Provenance: survey-form archetype visual reference board

- **Scope:** one illustrative JPEG for `survey-form`, an in-family training archetype (`tr-10` with the `fam-10` transit-survey variant, one of the sixteen in `src/eval/prereg.mjs`) rather than one of the five evaluation families. It exists because the archetype's plan asserts a validation-refusal contract - advancing with missing mandatory rating questions is refused with accessible warning messages that name the field and prevent submission - and the board set for that state was empty (`mwg-train-z5q7`, per [`reference-board-gaps.md`](reference-board-gaps.md)). This record exists so nobody has to guess which side of the boundary it sits on: **A1, planning reference only** - not an evaluation target, not a training example, not generated-site evidence.
- **Generation:** 2026-10-13 UTC, by `scripts/generate-archetype-boards.mjs --write --only survey-form`. The script passes `model: gemini-nano-banana-2.1` explicitly to the project's model gateway (`https://gemini.int.exe.xyz/v1beta/models/gemini-nano-banana-2.1:generateContent`, overridable with `MWG_TRAIN_IMAGE_ENDPOINT`) and fails closed unless the response's own `modelVersion` equals the requested model, so the board is gateway-attested `gemini-nano-banana-2.1`. Recorded settings: `responseModalities: ["IMAGE"]`, temperature 0.7, `maxOutputTokens` 8192; the board returned a 1376 × 768 JPEG. No seed was set, so the bytes are not reproducible from the prompt. The prompt is the one in the linked archetype README, and its exact UTF-8 digest is in the table below, so a regeneration can be proven to have used the same brief.
- **Rights:** [Google consumer-account terms](../accounts/google-antigravity-consumer.md) prohibit using AI-generated service content to develop machine-learning models. `excluded_from_training: true`; `approved_for_training: false`. No exclusive copyright, general image license, production or commercial reuse clearance is claimed, and no separate reuse/clearance document was supplied. Do not move this image into a corpus, an evaluation target, adapter or training work, or generated-site evidence. A visual review does not change that boundary.
- **Visual truth:** the authority name, question wording, rating labels, progress indicator and error strings are invented, unverified placeholders. The JPEG does not demonstrate a working survey flow, session-backed persistence, an accessible announcement or a validation engine, and it does not by itself satisfy the archetype's contract: the refusal behaviour is asserted by the plan and its verifiers, not by this picture.
- **Observed placeholder artefacts, inspected and accepted:** an independent vision review of this 2026-10-13 board (commissioned from a vision-capable model in a different family than the lane that produced it, which is text-only) returned ACCEPT. It quoted the banner "Some required questions still need an answer" and the inline message "Please choose a rating" on exactly the two unanswered questions, confirmed questions 1 and 2 keep their selected radio states with no red styling, read the progress indicator as "Step 2 of 4" (50%), and found "Continue" and "Back" available with no corrupted text in any primary position. This record does not imply the board was clean beyond what that review quoted.
- **Coverage:** one board, for the validation-refusal state only, under the plan's own slug for it (`step3-validation`, [`plan.md`](../../design/archetypes/survey-form/plan.md):130). Intro, questions, receipt and empty states are **not** pictured and must not be inferred from this image.
- **Where the state renders:** the questionnaire page is `/survey` in the training definition, but the refusal only exists after a refused advance, so `board-states.json` maps this board to a deliberately null path with a source - the convention the Wave 2 refusal boards and booking's `step4-error.jpg` established (mwg-train-wrsj, standard (a)). **Scope boundary:** as an interaction board it establishes the canonical visual reference under `kind: 'interaction'` with a null path, per the Wave 2 standard (booking `step4-error.jpg`; contact-lead, account-recovery and event-registration `step3-refusal`), and it is exempt from path-based comparator sweeps: `captureSignature` captures by URL, so reaching a validation refusal requires driving the refused submission, which is deferred to dynamic interaction capture in `check-cross-arm-parity` and is instrument work rather than a board task.
