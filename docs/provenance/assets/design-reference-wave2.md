# Provenance: Wave 2 archetype visual reference boards

- **Scope:** eleven illustrative JPEGs across `catalogue`, `contact-lead`, `account-recovery` and `event-registration`. They are visual planning references, not functional interfaces, real transactions, generated-site screenshots, training examples or sealed A6 targets.
- **Generation:** 2026-10-11 UTC for boards 1-9 and 2026-10-13 UTC for boards 10-11 (see the amendments below), regenerated with an EXPLICIT model. `scripts/generate-archetype-boards.mjs` passes `model: gemini-nano-banana-2.1` to the project's model gateway (`https://gemini.int.exe.xyz/v1beta/models/gemini-nano-banana-2.1:generateContent`, overridable with `MWG_TRAIN_IMAGE_ENDPOINT`) and fails closed unless the response's `modelVersion` equals the requested model, so all eleven boards are gateway-attested `gemini-nano-banana-2.1`. Recorded settings: `responseModalities: ["IMAGE"]`, temperature 0.7, `maxOutputTokens` 8192; each returned a 1376 × 768 JPEG. The prompts were edited on 2026-10-11 to ban window framing and enforce full-bleed edges. The generator strictly verifies them against this register's own prompt digests before it runs, so the updated hashes are pinned. SUPERSEDED: the 2026-10-09 generation (nine `generate_image` calls, no explicit model, reported as `gemini-3-pro-image`, output paths returned rather than model attestations, owner-rejected on sight, bead `mwg-train-c1c`); those byte digests remain in git history at the previous commit.
- **Amendment:** 2026-10-11, `catalogue/step3-empty.jpg`. The board showed the page inside a rounded panel floating on a ground - a presentation frame the frame gate cannot detect, as it looks only for macOS-style traffic lights (bead `mwg-train-6n77`). The prompt now leads with the requirement and states the palette roles explicitly: "Full-bleed desktop screenshot of a web application's own viewport ... no page container, no rounded panel around the page, no surrounding background margin ... The only background visible is the application's own page colour (#0f172a), and it reaches all four edges." The first attempt appended that requirement to the end of the original prompt; the generator reported it as 400756 bytes, but the worktree's file held the original bytes again afterwards, so what that attempt rendered is not established and this record does not claim it was framed. The original wording said "Dark slate theme (#0f172a, card surface #1e293b)", which leaves a model free to paint #0f172a as a ground and the whole application on a #1e293b card - which is what the previous board showed - so the prompt was rewritten to lead with the requirement and to state the palette roles. This is the catalogue-specific amendment: the other two catalogue prompts are untouched, and this row's prompt digest and JPEG bytes below are the amended pair. The amended prompt text and the reason are recorded in the [catalogue README](../../design/archetypes/catalogue/README.md).
- **Rights:** [Google consumer-account terms](../accounts/google-antigravity-consumer.md) prohibit using AI-generated service content to develop machine-learning models. `excluded_from_training: true`; `approved_for_training: false` for **all eleven**. No exclusive copyright, general image license or production/commercial reuse clearance is claimed. Do not move these images into corpus, evaluation targets, training, adapter work or generated-site evidence. Visual review does not change that boundary.
- **Visual truth:** invented products, addresses, prices, attendee identities, seat counts, reference tokens, QR graphics and UI control affordances are unverified placeholders. In particular, depicted success/confirmation states do not verify an email, payment, booking, real pass or accessibility behavior. Only the bytes and original prompt arguments are pinned here.
- **Observed placeholder artefacts, inspected and accepted:** an independent vision review of this 2026-10-11 set found no corrupted text in a primary position anywhere - the defect class that caused the previous set's rejection - and reported two cross-board consistency quirks, both in placeholder content that no prompt pins, left uncorrected because re-rolling a board for illustrative noise would discard a board that is otherwise correct: `contact-lead` shows a different studio name in `step1-form.jpg` than in `step2-success.jpg`, and `account-recovery` shows `STEP 1 OF 2` in `step1-request.jpg` but `STEP 2 OF 3` in `step2-sent.jpg`. These are recorded as observations, not as a claim that the labels are accurate.
- **Amendment (2026-10-13, `account-recovery/step3-refusal.jpg`):** an eleventh board, added by `mwg-train-uh0o`, same decision and same amended prompt form as the contact-lead amendment below: the account-recovery contract requires an empty or malformed address to be refused by the field's own constraint before submission, the error announced in text (plan.md:114), and no board depicted it. Gateway-attested `gemini-nano-banana-2.1`, same settings, 1376 × 768.
- **Amendment (2026-10-13, `contact-lead/step3-refusal.jpg`):** a tenth board, added by `mwg-train-cdp0` under the [reference-board-gaps](reference-board-gaps.md) decision: the contact-lead contract requires an invalid-submit refusal state (plan.md:54) that no board depicted. Generated by the same script and model (`gemini-nano-banana-2.1`, gateway-attested, same settings), 1376 × 768, and the prompt follows the amended catalogue form - it leads with the full-bleed/no-panel requirement and states the palette roles explicitly - rather than the older contact-lead wording that pre-dates the `mwg-train-6n77` lesson. Its prompt digest and JPEG bytes are pinned in the rows below like the rest.
- **Coverage:** these are the eleven actually supplied boards, not a complete error/empty/success set for every archetype. The catalogue includes an empty-search board; contact-lead and account-recovery now include their contract-required refusal boards; event-registration remains with the two pictured steps. Missing states beyond those must not be inferred or fabricated.
