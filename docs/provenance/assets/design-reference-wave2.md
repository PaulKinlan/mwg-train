# Provenance: Wave 2 archetype visual reference boards

- **Scope:** nine illustrative JPEGs across `catalogue`, `contact-lead`, `account-recovery` and `event-registration`. They are visual planning references, not functional interfaces, real transactions, generated-site screenshots, training examples or sealed A6 targets.
- **Generation:** 2026-10-11 UTC, regenerated with an EXPLICIT model. `scripts/generate-archetype-boards.mjs` passes `model: gemini-nano-banana-2.1` to the project's model gateway (`https://gemini.int.exe.xyz/v1beta/models/gemini-nano-banana-2.1:generateContent`, overridable with `MWG_TRAIN_IMAGE_ENDPOINT`) and fails closed unless the response's `modelVersion` equals the requested model, so all nine boards are gateway-attested `gemini-nano-banana-2.1`. Recorded settings: `responseModalities: ["IMAGE"]`, temperature 0.7, `maxOutputTokens` 8192; each returned a 1376 × 768 JPEG. The prompts are byte-identical to the previous generation - the generator verifies them against this register's own prompt digests before it runs - and appear in the linked archetype READMEs. SUPERSEDED: the 2026-10-09 generation (nine `generate_image` calls, no explicit model, reported as `gemini-3-pro-image`, output paths returned rather than model attestations, owner-rejected on sight, bead `mwg-train-c1c`); those byte digests remain in git history at the previous commit.
- **Rights:** [Google consumer-account terms](../accounts/google-antigravity-consumer.md) prohibit using AI-generated service content to develop machine-learning models. `excluded_from_training: true`; `approved_for_training: false` for **all nine**. No exclusive copyright, general image license or production/commercial reuse clearance is claimed. Do not move these images into corpus, evaluation targets, training, adapter work or generated-site evidence. Visual review does not change that boundary.
- **Visual truth:** invented products, addresses, prices, attendee identities, seat counts, reference tokens, QR graphics and UI control affordances are unverified placeholders. In particular, depicted success/confirmation states do not verify an email, payment, booking, real pass or accessibility behavior. Only the bytes and original prompt arguments are pinned here.
- **Observed placeholder artefacts, inspected and accepted:** an independent vision review of this 2026-10-11 set found no corrupted text in a primary position anywhere - the defect class that caused the previous set's rejection - and reported two cross-board consistency quirks, both in placeholder content that no prompt pins, left uncorrected because re-rolling a board for illustrative noise would discard a board that is otherwise correct: `contact-lead` shows a different studio name in `step1-form.jpg` than in `step2-success.jpg`, and `account-recovery` shows `STEP 1 OF 2` in `step1-request.jpg` but `STEP 2 OF 3` in `step2-sent.jpg`. These are recorded as observations, not as a claim that the labels are accurate.
- **Coverage:** these are the nine actually supplied boards, not a complete error/empty/success set for every archetype. The catalogue includes an empty-search board; the other three families have only the two pictured steps. Missing error states must not be inferred or fabricated.
